# Implementation Details: GitHub Copilot App Bilingual Workshop

## Context Reference

Sources: .copilot-tracking/research/2026-09-22/github-copilot-app-workshop-research.md is the authoritative baseline. Supporting evidence lives in .copilot-tracking/research/subagents/2026-09-22/workshop-scope-research.md, canvas-curriculum-research.md, publishing-deck-research.md, adversarial-product-verification.md, adversarial-curriculum-review.md, and adversarial-build-verification.md.

Discrepancy and path decisions are recorded in .copilot-tracking/plans/logs/2026-09-22/github-copilot-app-workshop-log.md.

Two constraints shape every phase. First, the research marks the reference canvas, timed rehearsal, and network preflight as blocking gates that cannot be satisfied by authoring alone; this plan produces the artifacts those gates consume and explicitly stops short of claiming they are met. Second, nothing in this plan may assert that an unrehearsed behavior works, so every generated page states what was tested and what was not.

### Step 1.1: Initialize repository tooling

Create the Node workspace that the deck generator and validators run in. Keep dependencies minimal and locked.

Files:
* package.json - ESM package (`"type": "module"`), Node engines constraint, scripts for `build:decks`, `validate:content`, `validate:decks`, `audit:deps`, and `validate:all`.
* package-lock.json - generated by `npm install`, committed.
* .gitignore - ignore `node_modules/`, `docs/assets/decks/`, `_site/`, `.jekyll-cache/`, and `Gemfile.lock` is explicitly NOT ignored.
* .editorconfig - UTF-8, LF, final newline. French content requires UTF-8 without BOM.
* SUPPLY-CHAIN.md - records the resolved dependency pins, the `npm audit --omit=dev` output, the audit date, and the explicit decision on the `https` transitive package.

Declare every runtime dependency explicitly, including the deck library and the ZIP or OOXML reader that Step 5.2 needs to open a `.pptx`. Do not leave a validator dependency implicit.

Fix the build output location once, here, and use it everywhere. Every Jekyll invocation in this plan runs from the repository root as `BUNDLE_GEMFILE=docs/Gemfile bundle exec jekyll build --source docs --destination _site`, so the built site is always `_site/` at the root and every assertion, link check, and artifact upload path refers to that same location. Do not rely on the default `docs/_site/`. The `BUNDLE_GEMFILE` prefix is load-bearing rather than decorative: the Gemfile lives in `docs/` and bundler resolves upward from the working directory, so a root invocation without it fails on any clean shell and on every CI runner. This correction was recorded during Step 7.1.

* Addresses BLD-H4: a production-dependency audit is run, recorded, and enforced, not just discussed.
* Escalates OD-01, recorded in the planning log with alternative IP-03; install the deck library version chosen there.

Success criteria:

### Step 1.2: Author the paired content model

Create one source of truth for content that appears in more than one surface. The research flags a drift problem across five surfaces - the English site, French site, English deck, French deck, and the root README agenda table; a shared model plus a validator is the mitigation.

Files:
* content/workshop-content.mjs - exports `sections` (six entries) and `slides` (sixteen entries). Each record carries a stable `id`, `durationMinutes`, optional `labId`, `translationKey`, and an `en`/`fr` pair for title, body, and speaker notes. Slide records also carry `sources` (official URLs) and optional `image`/`alt`.
* content/task-board-fixture.json - the synthetic seed fixture: `boardId`, tasks T001-T004 with paired EN/FR titles, `statusLabels`, and `priorityLabels`.

`durationMinutes` is per language, not shared. The research finding that French delivery runs longer at equal comprehension cannot be mitigated by a single shared duration set. Express it as `durationMinutes: { en, fr }`, and require that the French variant either reallocates minutes across sections within the same ninety-minute total or drops one checkpoint, with the choice recorded. The session envelope stays at ninety minutes in both languages, because the agenda, the deck grouping contract, and the booked session length all depend on it. The English values are what the root README is validated against; the French values are what the French tree and the French deck are validated against.

Use the exact agenda titles and durations from the research agenda table, and the exact slide grouping 01-03, 04-05, 06-08, 09-11, 12-14, 15-16.

The 16-slide outline in the publishing subagent research predates two corrections and must not be copied literally. It still names Interactive mode for agenda section 2, which is Plan mode, and it still allocates ten of the ninety minutes to a setup readiness check, which the research removed because installation and sign-in happen before the timed workshop.

Discrepancy references:
* Addresses BLD-H3: `translationKey` becomes machine-checkable instead of a naming convention, across all five content surfaces.
* Addresses CUR-H4 in part, by allowing the French budget to differ rather than forcing parity with English.
* Follows the research decision to keep identifiers, machine values, and lab slugs identical across languages.

Success criteria:
* Six sections whose English durations sum to 90 minutes in the order 10/15/30/15/15/5.
* Each section carries a French duration, the French durations also sum to 90 minutes, and the recorded reallocation or dropped-checkpoint decision is stated explicitly rather than assumed equal to English.
* Sixteen slides with ids 01-16 used exactly once, whose per-group durations match their section durations.
* Every record has non-empty `en` and `fr` values; no French value is a copy of its English counterpart.
* Slide 04 names Plan mode; the word Interactive does not appear as the mode for agenda section 2.
* No slide allocates workshop time to installation, sign-in, or a setup readiness check.
* The fixture parses as valid JSON with four unique task identifiers.

### Step 1.3: Author the content parity validator

Write the validator before the content it validates, so authoring errors surface immediately rather than at the end.

Files:
* scripts/validate-content.mjs - asserts the content model invariants from Step 1.2, then walks `docs/` and `docs/fr/` to assert that every page has a counterpart with the same `translation_key`, the same lab slug, and a `lang` value matching its tree.

The validator exposes five explicit modes, because Phases 3 through 6 run in parallel and must not perform cross-tree or post-build checks:
* Default, no flags: full parity across all five surfaces, including counterpart matching, README alignment, slug policy, and the post-build base path assertion.
* `--structure-only`: front matter well-formedness, `covers:` marker presence, and alignment with the content model, scoped to whatever trees are supplied. Skips counterpart matching, README parsing, and the base path assertion.
* `--tree <path>`: restricts the walk to one tree, repeatable so a step can name several disjoint subtrees. Absent this flag the walk covers the whole repository.
* `--exclude <path>`: repeatable, prunes a subtree from the walk. Required because the English tree root physically contains the French, facilitator, and asset subtrees that other parallel phases own, so `--tree` alone cannot express one phase's write scope.
* `--basepath-only`: runs the post-build assertion alone against an already-built `_site`, so it can be sequenced after a Jekyll build rather than before one.

An unknown flag must exit non-zero rather than silently falling back to full mode.

The validator must exit non-zero on any failure and print the offending file and key. A missing counterpart is an error, not a warning.

The validator covers five content surfaces, not two trees. It must additionally:
* Parse README.md and assert that its six section headings and durations match `content/workshop-content.mjs` exactly.
* Assert required-content markers, not just keys. Every page declares a `covers:` front matter list, and the validator asserts that specified markers appear in both language counterparts. A French page missing a safety-critical statement must fail even though its `translation_key` matches.
* Assert the slug policy: French entry pages use localized slugs, while lab and facilitator slugs stay identical to English. Any French lab or facilitator slug that diverges is an error.
* Assert, after a Jekyll build, that a known asset href in `_site/index.html` begins with the expected base path. This assertion reads the build output fixed in Step 1.1 and must fail loudly when `_site` is absent rather than passing by default.

Discrepancy references:
* Addresses BLD-C3: this is a real check, replacing self-referential validation.
* Addresses BLD-H3 across all five surfaces including the README.
* Addresses BLD-H1 with an automated post-build base path assertion rather than a human judgement.
* Addresses the navigation caveat that a wrong `grand_parent` silently drops a page while the build still exits zero.

Success criteria:
* Running the validator against deliberately broken fixtures fails with a clear message, including a README whose durations were edited and a French page missing a required `covers:` marker.
* Running it against a matched pair passes.
* Front matter parsing handles accented French characters without corruption.
* The base path assertion fails when the site is built without the expected base path, and fails when `_site` does not exist.
* `--structure-only`, `--tree`, and `--exclude` behave as specified, an excluded subtree is demonstrably not walked, and an unknown flag exits non-zero.
* Each language tree is validated against its own language's `durationMinutes`, both language totals are asserted at 90 minutes, and a longer French budget is rejected rather than reported as drift.

* .copilot-tracking/research/subagents/2026-09-22/adversarial-build-verification.md - findings C3, H1, H3, and the silent-nav-drop caveat.

* Step 1.2 completion.

### Step 5.2: Write the deck validator

Files:
* scripts/validate-decks.mjs - opens each generated `.pptx` as a ZIP and asserts per-slide bilingual correctness.

An aggregate comparison is not enough. A deck pair where slide 01 is translated and the remaining fifteen are identical English would pass an aggregate difference check, which is the same fail-soft defect the check exists to prevent. Assert per slide:
* Both decks contain the same slide count and the same slide id ordering.
* For every slide id, the English and French extracted text differ.
* The French deck's accented-character ratio exceeds a declared threshold, computed across all slides.
* The expected slide-id token appears at the expected index in each deck.
* Every notes part contains its own slide's source URLs, not merely some URL.
* No deck file is missing or zero bytes.

Discrepancy references:
* Addresses BLD-H5 using its stated mitigation rather than a weaker aggregate restatement.
* Addresses BLD-C1's fail-soft variant by treating a missing or zero-byte deck as a failure.

Success criteria:
* Validator fails when handed two identical decks.
* Validator fails when only one slide differs between the decks.
* Validator fails when a deck is missing, empty, or has fewer than sixteen slides.
* Validator fails when a notes part carries another slide's source URLs.
* Validator passes on correctly generated output.
