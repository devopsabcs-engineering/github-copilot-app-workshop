CHANGE: one sidebar renders both language groups, so a link whose target language differs from the surrounding document is a change in the language of a part (WCAG 3.1.2). Every link now declares its own target language. The expander button's aria-label embeds the target page title, so it is marked the same way. The marking is ABSOLUTE, not relative to the page being rendered. That is required, not a stylistic choice: components/site_nav.html is pulled in with `include_cached` and is documented as depending on `site` alone, so the sidebar is rendered once and reused on every page. Deciding the attribute by comparing against `page.lang` would make this include page-dependent while the cache kept serving the first page's answer, which yields a sidebar that is right in one language and silently wrong in the other. Marking a link in the document's own language is redundant rather than harmful, and redundancy is the correct trade against a cache-dependent defect. Emitting the attribute is not evidence that the announcement changes. The screen reader verification is a separate task (Step 8.1). The loop and its conditions are unchanged, so no page can disappear from navigation as a result of this override. {%- endcomment -%} {%- comment -%} Include as: {%- include components/nav/links.html pages=page_array ancestors=title_array all=bool -%} Depends on: include.pages, include.ancestors, include.all.
